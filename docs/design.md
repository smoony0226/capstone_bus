# BUS1 치수 뷰어 설계

## 목적과 범위

2026-10-03 사용자 요청: 참고 뷰어처럼 우리 버스의 치수를 확인하는 정적 웹 뷰어.
BUS1을 공통 차체 기준으로 사용한다. 외관·실제 센서·배터리 덮개와 탈착 표현, 하단 상세 정보만 포함한다.
배터리함은 사용자 요청에 따라 탈부착을 이해할 수 있는 간단한 표현으로 충분하다.
실시간 차량 데이터나 하드웨어 명령을 보내지 않는다.

## 실측 계약

단위 mm. x는 차량 종방향(앞이 +), y는 지면으로부터 높이, z는 좌우.
앞범퍼 x=470, 뒤끝 x=-470. 앞축=280, 뒷축=-130, 축거=410.
전장 940, 전폭 180, 닫힌 상태 최대 전고 230. 바퀴 지름 83, 사용자 제공 둘레 260.8.
둘레는 π×83을 소수 첫째 자리까지 표시한 값과 일치한다. 제공 값을 보존한다.
축 위치·바퀴·휠 아치·치수선은 같은 데이터로 계산한다.

외장 세부 형상은 제공 사진 5장을 참고한 단순화 모델이다.
사진에서 앞부분 교환 공간, 그 뒤 녹색 상부 하우징, 뒤쪽 begins 표기, 검은 창문 띠와 두 승강문을 읽었다.
전체 전고 안에서 기본 지붕을 205, 상부 하우징을 230으로 두었다. 기본 지붕 높이는 실측값이 아니다.
배터리함의 앞뒤 범위·폭·개방 110도·탈거 125mm는 시각화용 가정이며 치수 표에 실측값으로 노출하지 않는다.
추가 사진이나 실측에서 덮개 대상·힌지 방향이 다르면 `appearance`와 교환부 모델을 수정한다.

## 데이터와 책임

`data.js`가 치수와 형상 가정의 원천이다. 모순되는 치수는 검증에서 실패한다.
`model.js`는 메시에 책임을 갖고 카메라·덮개·배터리 그룹 참조를 반환한다.
`dimension-lines.js`는 기하학 치수선과 화면 라벨의 투영을 담당한다.
`app.js`가 화면 상태를 단독 소유하며 모듈에 값을 전달한다. 시점·레이어 변경은 모델을 재생성하지 않는다.
렌더링 초기화 실패는 치수 표·참고사진을 유지하고 3D 조작을 비활성화한다.

## 시스템 설명 근거

사용자 제공 개요 및 `racer_ws`의 `README.md`, `docs/design.md`,
`src/racer_sensors/config/bus-01.yaml`, `firmware/bus1_esp/bus1_esp.ino`를 확인했다.
전방 OAK-1 RGB, 후방 OAK(정확한 모델 미확정), 9축 IMU, 모터축 100PPR 단채널 엔코더를 표시한다.
카메라 설정 640×480 / 30Hz, IMU 폴링 50Hz / 115200baud, 엔코더 텔레메트리 10Hz는 설정/펌웨어 값이다.
실제 달성 처리율을 의미하지 않는다. 센서의 장착 좌표는 아직 실측하지 않았다.
차선은 PIDNet, 장애물은 YOLO11n-seg. 모드 상태기계와 안전 판단 후 drive_adapter의 drv 명령이
UART로 ESP32에 전달되고 모터·서보를 구동한다. 관제·스테이션 비전·교체 로봇팔은 하단 설명에만 포함한다.

## 검증

치수 일관성과 잘못된 입력의 실패를 Node 시험으로 검사한다.
브라우저에서 실제 메쉬의 닫힌 경계 940×180×230, 지면·시점·토글·교환부·모바일·오류 표시를 확인한다.
사용자 제공 치수를 기준으로 검증하며 제조사 CAD나 실물 정밀 측정에 대한 검증은 아니다.
